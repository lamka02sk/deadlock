Brief for the implementer. Scope is PLAN.md "Milestone 6 → Shared groundwork" and "Phase 15". Do not widen it.
Before writing Rust, load `.claude/skills/rust-skills/SKILL.md` and follow it.

## 1. Goal and done-when

- Every attribute of an existing column can be changed from the Structure view without losing another one, on MySQL 8.4, MariaDB 11 and Oracle Free: name, type + length, collation (MySQL), null, default, on update (MySQL), auto_increment, comment, generation expression (generated columns), position (MySQL).
- Groundwork: `run_ddl` runs a list of statements; `column_definition()` is shared by Add column, Edit column and (Phase 18) Create table; Oracle Add column with a comment works (2 statements).
- Read-only connections disable every Structure action (buttons, row menu items, double-click), the same way `object_menu` does (`.disabled(read_only)`).
- **Done when:** the unit tests and the `engines.rs` cases below pass, and in the app an edit of each attribute on each engine leaves the others intact (re-read shows them unchanged).

**New functions** (all `pub`, all return `Result<_, String>` with user-facing reasons, as the existing ones):

1. `pub fn column_definition(c: &NewColumn, key: Option<&str>, s: &TableStructure) -> Result<String, String>`
   - The column as it appears inside `add column …` / `change column old …` / `create table (…)`: name + definition, **no position**. `key` is `Some("primary key" | "unique key")` only for an auto_increment column that still needs a key.
   - MySQL / MariaDB, plain column (order matters for the existing unit tests, keep it):
     `` `name` <full_type>[ collate X] null|not null[ default D][ on update current_timestamp[(N)]][ invisible][ auto_increment[ <key>]][ comment 'c'] ``
     - auto_increment: writes `not null auto_increment[ key]`, no default, no on update (as today).
     - `collate X` only when `collation` is `Some` **and** the base type is textual (`char varchar tinytext text mediumtext longtext enum set`); X must match `[A-Za-z0-9_]+`.
     - `on update`: only when `on_update` and base type is `datetime`/`timestamp`, else `Err("on update needs a datetime or timestamp column")`. N = the length field (fsp); empty or `0` → bare `current_timestamp`, else `current_timestamp(N)` (MySQL error 1294 otherwise).
   - MySQL / MariaDB, generated (`c.generated = Some(g)`):
     `` `name` <full_type>[ collate X] generated always as <g.expression> stored|virtual[ null|not null (MySQL only, skip when s.mariadb)][ invisible][ comment 'c'] `` — no default, no auto_increment, no on update (Err if set).
   - Oracle: `"NAME" <oracle_type>[ generated by default as identity| default D][ not null]` (exactly today's `oracle_add_column` body minus `alter table … add (` / `)`). Generated on Oracle: `"NAME" [type ]as <expr> virtual`. `on_update` → `Err("Oracle has no ON UPDATE: use a trigger")`. Comment is **not** part of it (separate statement).
   - Ends with `one_statement_in(.., engine)` on the full statement in the callers (not here).
2. `add_column_sql` → **returns `Result<Vec<String>, String>`**. MySQL: `vec![format!("alter table {q} add column {def}{position}")]` with `def = column_definition(c, key_for_new_ai, s)` (key rule unchanged: `unique key` if a PK exists, else `primary key`). Oracle: `alter table {q} add ({def})`, plus `comment on column {q}.{ident} is '{c}'` when the comment is not empty (remove today's refusal). Position ≠ Last on Oracle still refused.
3. `impl NewColumn { pub fn from_existing(c: &StructureColumn, s: &TableStructure) -> NewColumn }` — the inverse:
   - `name`, `nullable`, `default` (copy; see the mysql.rs normalisation below), `comment`, `collation`, `generated`, `on_update = c.on_update.is_some()`, `auto_increment = extra contains "auto_increment"` (MySQL) / `extra starts with "generated "` (Oracle identity), `invisible = extra contains "INVISIBLE"` (case-insensitive).
   - `position`: index 0 → `First`, else `After(previous column name)` (from `s.columns`).
   - Type split (`split_type(column_type, oracle) -> (String, String)`, private, unit tested):
     - MySQL: `base(len) rest` → `(format!("{base} {rest}").trim(), len)`: `decimal(10,2) unsigned zerofill` → (`decimal unsigned zerofill`, `10,2`); `bigint(20) unsigned` → (`bigint unsigned`, `20`); `datetime(3)` → (`datetime`, `3`); `int` → (`int`, ``). `enum(…)`/`set(…)`: members unquoted (`'it''s'` → `it's`) joined with `, ` (members containing `,` cannot round-trip: see risks).
     - Oracle (`type_label` output): `number(10,2)` → (`number`,`10,2`); `number(*,0)` → (`integer`, ``); `varchar2(40 char)` → (`varchar2`, `40 char`); `timestamp(6) with time zone` → (`timestamp with time zone`, `6`); anything else unparsable → (whole text, ``) as free text.
   - Types not in `column_types(mariadb)` / `ORACLE_TYPES` stay as free text (the UI appends them to the Select's list).
4. `pub fn modify_column_sql(t: &TableRef, old: &StructureColumn, new: &NewColumn, s: &TableStructure) -> Result<Vec<String>, String>`
   - MySQL / MariaDB: one statement `alter table {q} change column {old_ident} {column_definition(new, key, s)}{position}` where position = ` first` | `` after `x` `` | nothing for `Last`. `key` = `None` if `old` is already the first part of any index (`s.indexes.iter().any(|i| i.parts.first().is_some_and(|p| !p.expression && p.column == old.name))`), else the add rule. Returns the statement even when nothing changed (the round-trip test relies on it; the UI blocks no-op Apply).
   - Refusals (both MySQL flavors): `old.generated.is_some() != new.generated.is_some()` → `Err("a generated column stays generated: drop it and add a new one")`; stored ≠ stored → `Err("MySQL cannot switch a generated column between stored and virtual: drop it and add it again")`.
   - Oracle: diff `before = NewColumn::from_existing(old, s)` against `new`, in this order:
     1. name changed → `alter table {q} rename column "OLD" to "NEW"`
     2. one `alter table {q} modify ("NEW"<parts>)` when any part changed: type `(data_type,length)` changed → ` <oracle_type>`; default changed → ` default <oracle_default or null>` (empty = `default null`); nullable changed → ` null` / ` not null` (**only when changed**: ORA-01451 / ORA-01442); generated expression changed → `modify ("NEW" as (<expr>))` instead (separate statement).
     3. identity: `before.auto_increment && !new.auto_increment` → `alter table {q} modify ("NEW" drop identity)`; `!before && new` → `Err("Oracle cannot make an existing column an identity column")`.
     4. comment changed → `comment on column {q}."NEW" is '<c>'` (`''` clears it).
     - `position != before.position` → `Err("Oracle cannot reorder columns")`; `on_update` → the column_definition Err; nothing changed → `Ok(vec![])`.
   - Every statement passes `one_statement_in`.
5. `oracle_type`: accept `N char` / `N byte` as the length of `varchar2` / `char` (`varchar2(40 char)`).

## 3. SQL per engine

| Operation | MySQL 8.4 | MariaDB 11 | Oracle Free 23 |
|---|---|---|---|
| Edit (any attribute) | `` alter table `d`.`t` change column `old` `new` varchar(40) collate utf8mb4_bin not null default 'x' comment 'c' after `id` `` | same; generated columns without `null`/`not null` | up to: `rename column "OLD" to "NEW"`; `modify ("NEW" varchar2(40) default 'x' not null)`; `comment on column "S"."T"."NEW" is 'c'` |
| ON UPDATE | `datetime(3) … default current_timestamp(3) on update current_timestamp(3)` (fsp must match, error 1294) | same | refused: use a trigger |
| Auto increment, already a key | `bigint unsigned not null auto_increment` (no extra key) | same | `modify ("ID" drop identity)` to remove; adding refused |
| Auto increment, not a key yet | `… auto_increment unique key` (PK exists) / `primary key` | same | refused |
| Generated | `int generated always as (expr) virtual null comment 'c'`; stored↔virtual refused | `… stored` (MariaDB accepts `STORED` = `PERSISTENT`), no null clause | `modify ("C" as (expr))` (virtual only) |
| Move | `change column x x <def> first` / `after y` | same | refused |
| Add with comment | 1 statement | 1 | `alter table … add (…)` + `comment on column …` |

Version notes: `CHANGE COLUMN` works on MySQL 5.7+ and every MariaDB (so no `RENAME COLUMN`, which needs MySQL 8.0 / MariaDB 10.5.2). `COLLATE x` without `CHARACTER SET` takes the collation's charset (MySQL and MariaDB). Expression defaults `DEFAULT (expr)` need MySQL 8.0.13+ / MariaDB 10.2+. **Unsure, verify in the engines test:** MariaDB rejecting `NULL` after a generated column definition (assumed from its grammar); Oracle `MODIFY (c AS (expr))` on a virtual column (documented as `modify_virtcol_properties`).

## 8. Risks / open questions

- `enum`/`set` members containing `,` cannot round-trip through the comma-separated Length field (existing limitation of `full_type`); the round-trip test must not use one. Flag in the report if hit.
- MySQL spatial `SRID n` (8.0) and MariaDB column-level `CHECK` (e.g. the `json_valid` check MariaDB attaches to `JSON` columns) are not restated by `CHANGE`; a MariaDB JSON column edit may drop its `json_valid` check. Verify on MariaDB 11 and report; do not fix in this phase.
- Oracle quoted names are case-sensitive; the edit keeps the convention of the Add form (names as typed).
